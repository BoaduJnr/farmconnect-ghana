1. Project Overview

FarmConnect Ghana is a mobile-first, bilingual (English/Twi) marketplace connecting Ghanaian smallholder farmers directly to buyers, live market prices, and an AI-powered agricultural advisor — with a full SMS command channel so feature-phone users with no data plan can participate too. Built as the CSCD602 Advanced Software Engineering capstone by Group Angry Nerds, University of Ghana.

2. Main System Features

  • Phone + OTP authentication (no passwords), role-based (Farmer / Buyer / Administrator).
  • Produce listings with photos, quantity, price, harvest date, and GPS location; buyer search/filter by crop, category, price, and distance.
  • End-to-end order lifecycle with manual, zero-custody Mobile Money payment reconciliation and an administrator-arbitrated dispute path.
  • Live, continuously-updating per-crop price feed.
  • AI advisory chatbot (Google Gemini) with text + photo-based pest identification, weather-aware.
  • In-app + SMS notifications for every order/admin event.
  • Farmer cooperative (co-op) groups with join codes and leadership succession.
  • Mutual 1–5 star ratings feeding a per-user trust score.
  • Full SMS command channel (HELP, REG, MOMO, LIST, PRICE, ORDERS, CONFIRM) for feature-phone users.
  • Admin Portal — account verification/suspension, listing moderation, dispute resolution.
  • Installable, offline-capable Progressive Web App with a full bilingual and accessibility pass.

5. Test Credentials

There are no fixed passwords anywhere in this system — authentication is phone number + a one-time code. No GiantSMS account is funded on this free-tier deployment, so the API deliberately echoes the code back in the OTP-request response (as devCode) instead of silently stranding every user — see §9.3 of Testing_Report.pdf and the code comment in auth.service.ts. To test as a Farmer or Buyer:

  1. Open the live application URL.
  2. Enter any Ghanaian-format phone number (e.g. 0551234567) not already registered.
  3. Request the code, then read it straight off the "OTP sent" screen — the app auto-fills it in non-production-gateway mode.
  4. Choose Farmer or Buyer on first login.

6. Admin Access

There is no self-service admin sign-up. A reserved administrator account is already seeded against the production database specifically for grading:

Examiner account (recommended)Phone 0200000001 — one-time code is always 123456 for this number specifically, so it can be used directly without reading an API response.

That phone number logs in through the same phone+OTP screen as everyone else and lands in the Admin Portal. New admins can be seeded the same way at any time: DATABASE_URL="<production connection string>" npx tsx apps/api/prisma/seed.ts --phone <number> --name "<name>" (Deployment_Guide.pdf Step 8).

7. Deployment Information

Deployed on an entirely free-tier stack: Vercel (static PWA), Render (API, free web service — sleeps after ~15 min idle, ~30–50s cold start on first request after), Supabase (managed Postgres 16), Upstash (managed Redis). Both Vercel and Render redeploy automatically on every push to master. Full step-by-step deployment instructions are in Deployment_Guide.pdf.

8. Known Limitations

  • Payments are manually reconciled, not automated escrow (see SRS §9.1).
  • Market prices are a realistic simulation, not a real Ghana Commodity Exchange feed (see SRS §9.2).
  • 10,000-concurrent-user and 99.5%-uptime targets are architecturally plausible but not load-tested at this submission's scale (see Testing_Report.pdf §11).
  • Render's free tier cold-starts after idling — the first request after a quiet period may take 30–50 seconds.

9. Special Instructions for Testing

  • To test the AI advisor, a GEMINI_API_KEY must be configured on the Render service (Deployment_Guide.pdf Step 4) — without it, the advisor deliberately fails with a clear 503 rather than fabricating a response.
  • To test the full farmer flow, Mobile Money details must be linked first (Profile → Mobile Money) — listing creation is blocked until this is done, by design.
  • The full end-to-end test evidence already captured for this build (69 automated tests + 11 manual smoke tests, all passing) is in Testing_Report.pdf — useful context if any behaviour looks unexpected during live testing.
